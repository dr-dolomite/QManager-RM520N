# 🚀 QManager RM520N BETA v0.1.14-draft

Custom SIM Profiles gets a full redesign and absorbs Connection Scenarios, so one page now opens by telling you exactly what your modem is running right now — the profile in force, the scenario it's bound to, and a 24-hour strip of when that scenario changes today — with a guided step-by-step wizard for creating profiles and ready-made suggestions for eight carriers. QManager also remembers your SIM cards properly now: a new **Tracked SIMs** list in System Settings shows every SIM the modem has seen, and the "New SIM card detected" banner finally stays dismissed for good, per SIM, on the device itself. The dashboard's **Speed Test** has been rebuilt too, with a live stepper, a full result panel, and a tile that picks up a test you started anywhere else. And **Cellular and Radio Information** has been redesigned from the ground up: every band you're on gets its own expandable row with real per-carrier signal readings, and the page finally tells you when its numbers have stopped updating. **SMS Center** has had the same treatment — separate storage meters for your modem and your SIM, an inbox that stays on screen when the modem is busy, and honest progress when you clear everything out.

> One-click OTA from **System Settings → Software Update** if you're on v0.1.5 or newer.

## ✨ New Features

- **See exactly how your bands stack up, on one strip.** The dashboard's Secondary Carriers card is replaced by a full-width **Carrier Aggregation** strip: a proportional bar where each band's width is its real bandwidth, plus a tile per carrier with its role, PCI, ARFCN, and signal meter. On 5G NSA the 5G leg is labelled **NR Anchor** instead of "secondary", since it is the carrier doing most of the work (role is derived in the interface only; the modem's own reporting is untouched).
- **A dropped band no longer just disappears.** If a carrier is released, its segment stays in place greyed with a "Released 3 min ago" note before fading out, so you can see what you lost instead of watching the strip silently redraw (a 6 second grace period keeps a momentarily missed radio read from flickering the whole strip).
- **Ready-made profiles for your carrier, right in your profile list.** Insert a SIM and **Cellular → Custom SIM Profiles** adds ready-made setups — APN and TTL already filled in — straight into your **Saved Profiles** list, marked **Suggested** and sitting below the profiles you actually saved. Recipes cover T-Mobile, T-Mobile Home Internet, Verizon, AT&T, Smart, Globe, GOMO, and DITO. Each one shows exactly what it will configure before you press Create, disappears once you have a profile for that SIM, and comes back if you delete it (the T-Mobile pair also includes a 5G band lock, checked against what your modem actually supports before anything is applied; the other carriers set APN and TTL only, so your Band Locking page stays available).
- **Prepaid and reseller SIMs are left alone.** SIMs from resellers that ride a bigger carrier's network — Mint, Google Fi, US Mobile, Visible, Cricket, Metro and others — no longer get their host carrier's suggestions, since those need a different APN. The check reads the service-provider name written on the SIM itself, which is the only place a reseller's identity actually appears.

- **See every SIM QManager remembers.** A new **Tracked SIMs** card in **System Settings** lists each SIM by carrier, phone number, and the date it was first seen, marks the one currently in the modem, and shows whether it still raises a new-SIM alert. SIMs already known to your device appear on the list after updating, with alerts already switched off (existing SIMs are backfilled from the known-SIMs list; historical entries show "Added before tracking began" rather than a made-up date).

- **QManager now tells you when your signal won't sit still.** If the modem keeps hopping between bands or cells, Recent Activities raises a single amber **"LTE band unstable — 14 changes in the last 5 min"** instead of one row per hop, so a genuinely flapping connection stands out rather than hiding in the noise (six changes inside five minutes trips it, and it's rate-limited to one warning per window).

- **The Speed Test has been rebuilt, start to finish.** Open it from the dashboard's Live Latency card and every stage now has a proper screen — a Latency → Download → Upload stepper that fills in as each measurement lands, big live readouts in the colour of whatever is being measured, and a full result panel with jitter, packet loss and the server you hit. If a run fails partway it now says *which* step died and keeps whatever it already measured, instead of throwing the whole thing away.
- **A test you started somewhere else now shows up on the dashboard.** Start a speed test in another tab — or from another device on your network — and the Live Latency card's Speed Test tile picks it up on its own, showing the live phase and reading without you opening anything (the tile polls a light 10-second heartbeat and speeds up only while a run is actually in flight).

- **Every band you're on, with its own signal readings.** **Cellular → Cellular and Radio Information** now lists one row per carrier — tap any of them to see that band's own RSRP, RSRQ, SINR and RSSI with meters, plus its exact frequencies, bandwidth, PCI and 5G subcarrier spacing. A value the modem didn't report says so instead of showing an empty bar, and anything the page worked out for itself rather than read from the radio is marked **Derived**.
- **Copy your radio diagnostics in one tap.** A **Copy diagnostics** button on the same page puts a tidy text summary of your network type, operator, aggregate bandwidth and every carrier's readings on the clipboard, ready to paste into a support thread. It deliberately contains no IMEI, ICCID, IP addresses, DNS, cell IDs or APN, so it's safe to post publicly without checking it first.
- **Turn the new-SIM alert back on for any SIM.** If you dismissed the "New SIM card detected" banner and want it back — say you're testing a profile — hit **Show Alert** on that SIM's row in Tracked SIMs and the banner returns, no reboot or reload needed.

- **Antenna Statistics has been rebuilt.** **Cellular → Antenna Statistics** now opens with a strip showing your MIMO layers, serving mode and how many of your four chains are reporting, above one card per radio holding all four ports with RSRP, RSRQ and SINR meters and a quality verdict on each. Every port keeps its place whether or not it's reporting, so a dead or unplugged antenna is obvious instead of quietly vanishing from the list.

- **Antenna Alignment now gives you one number to aim by.** **Cellular → Antenna Alignment** opens with a live **Live Aim** score out of 100, alongside the two readings behind it, their weights, your best score so far this session, and how much it just moved — so you can rotate an antenna and watch for improvement instead of reading four columns of dBm. The position recorder below it speaks the same score, so a live 74 and a recorded 78 mean exactly what you'd expect.

- **Your profiles and scenarios are one page now, and it opens with what's actually running.** **Cellular → Custom SIM Profiles** leads with an **in force now** card — the active profile, its APN and TTL, the connection scenario it's bound to, and the radio settings that scenario owns — with your saved profiles and every scenario side by side underneath. Connection Scenarios is no longer a separate sidebar item; old links to it land on the right place automatically.
- **See your whole day's scenario schedule at a glance.** If your active profile switches scenarios on a schedule, the new card draws it as a 24-hour strip with a marker on the current time, so "Gaming takes over at 18:00" is something you can see rather than work out (each profile row carries a miniature of the same strip, and both read from one shared calculation so they can't disagree).

## 🛠️ Improvements

- **The apply steps now tell you what they actually did.** Activating a profile shows a **Details** list where every step carries its own result — the APN that landed, "already set" for a step that was skipped, or the exact modem error for one that failed — instead of just a tick. If a step fails, the button offers **Reapply profile** and says plainly that the whole sequence runs again, because the modem has no way to retry a single step.
- **Deactivating a profile now puts your APN back to the carrier default.** Switching off the active profile under **Cellular → Custom SIM Profiles** used to leave the modem on that profile's APN and simply remove the "Active" badge — so deactivating didn't actually undo what applying did. It now reverts properly, and the confirmation dialog says so instead of promising nothing will change (expect the same brief cellular drop as applying; your IMEI and TTL settings are still left alone).
- **Creating a profile no longer takes up half the page.** The four-step wizard moved into a dialog opened by **New profile**, so the page stays focused on what your modem is doing rather than on a form you're usually not filling in.
- **The sign-in and welcome screens have been redesigned.** The public status page at `/` and the login screen now use the same tonal look as the rest of the refresh — filled band pills, rounded signal rows, and clearer notices instead of faint tinted boxes (both screens share one type scale and one icon set, and now carry a theme toggle and language picker side by side).
- **Mistyping your password no longer costs you five minutes.** Log in wrong once too often and you're locked for 30 seconds — then 2, 5 and 15 minutes only if the wrong guesses keep coming, so an owner who fumbles is straight back in while a script gets buried. The form also tells you how many tries are left before it locks, and the countdown now survives a page refresh.
- **The LTE and 5G cards on the dashboard got a refresh.** Signal readings now sit on rounded tinted rows with a filled quality chip, so "Excellent" or "Poor" reads at a glance instead of hiding in the colour of a number, and the band name gets its own coloured pill (part of the ongoing move to the new tonal design language).
- **You can tell the LTE and 5G cards apart from across the room.** The quality chip on each dashboard signal card is now coloured by radio — blue for 5G, violet for 4G — while signal quality itself is shown by the number of bars in the chip's icon, so quality still reads in greyscale, in sunlight, and to colour-blind eyes.
- **Every dashboard reading now says its quality out loud to a screen reader.** Values like SINR and RSRP add a hidden "Good" or "Fair" word alongside the colour, because green and amber sit at almost identical brightness and merge completely under the most common form of colour blindness.
- **A dropped connection now looks dropped.** The Network Status orb's failed state has a proper red ring instead of a grey one with a single red tint, and it stays still while a healthy connection pulses — so colour tells you how bad it is and motion tells you whether anything is alive.
- **One icon style across the whole dashboard.** The dashboard was drawing from four different icon sets at once; every card now uses the same rounded set as the sidebar, with bigger, clearer glyphs in the status orbs (the bundled icon font grew by about 9 KB and is still served entirely from the modem, so nothing is fetched from the internet).
- **The entire Cellular section now matches, too.** Cell Scanner, Band Locking, SMS Center, APN Management, Antenna Alignment, Tower Locking, Custom SIM Profiles and every other page under **Cellular** now use the same rounded icon set as the Cellular and Radio Information page they sit beside, instead of switching styles the moment you tap into one (the bundled icon font grew by about 9 KB to cover it, still served entirely from the modem).
- **Custom SIM Profiles has a whole new look.** Creating a profile is now a guided four-tab wizard — Identity, Network, Scenario, Review — with Load-from-SIM quick-fill, a "use my saved APN" pick, a live duplicate-SIM warning, and a summary step before you save. Saved profiles now show as stacked cards with config pills, a live dot on the active one, and an "Applied/Partial/Failed at HH:MM" line, instead of a plain table. Find it under **Cellular → Custom SIM Profiles**, fully translated in all five languages (frontend-only redesign ported from the RM551E build — the profile data model and 4-step apply pipeline are unchanged; Verizon-specific UI is intentionally omitted since it doesn't apply to this modem).
- **Custom SIM Profiles and Connection Scenarios now match the rest of the tonal refresh.** Profile rows, scenario tiles, and the apply-progress dialog under **Cellular → Custom SIM Profiles** use the same filled tonal containers as the dashboard and radio pages instead of faint tinted washes, with a tile and its loading skeleton finally sharing one radius.
- **Connection Scenarios now speaks all five languages.** The scenario picker, tiles, and active-config card under **Cellular → Custom SIM Profiles → Connection Scenarios** are fully translated into English, Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano), and Indonesian (Bahasa Indonesia).
- **The new-profile form fills itself in from your SIM.** Open the create form under **Cellular → Custom SIM Profiles** and your SIM's APN and ICCID appear on their own, without pressing Load from SIM — and anything you've already typed is left alone if the read finishes while you're mid-sentence. IMEI is still only filled by pressing **Load from SIM**, on purpose: a stored IMEI reboots the modem when the profile is applied.
- **A clearer "New SIM card detected" banner.** The banner now names the SIM's carrier and phone number instead of just announcing a swap, and offers exactly one next step: **Apply Profile** when a saved profile matches the card, or **Create Profile** when none does — which now drops you straight into the profile creation form.
- **Dismissing the banner asks first, and says what it means.** Closing the banner now opens a short confirmation that spells out the SIM's ID and makes clear you're silencing the alert for *that SIM only* — every other card still raises it, and you can undo it from Tracked SIMs.
- **Remembered SIMs live with the list they belong to.** The SIM count and its **Clear** button moved off the System Settings card and onto the bottom of **Tracked SIMs**, right under the SIMs they act on — so System Settings is back to just display preferences, and Clear can no longer leave the list showing SIMs it claims to have forgotten.
- **Cellular and Radio Information has been redesigned.** The page under **Cellular** now opens with four summary tiles — network type, total bandwidth, carrier count and MIMO — above a cleaner cell-information card and the new per-band list, in the same tonal style as the rest of the refresh (part of the ongoing move to the new design language; the page reads the same data as before and makes no extra requests to the modem).
- **The radio page now tells you when it's registered and when it isn't.** No SIM, airplane mode, no service or still searching each get their own clear screen with a Retry button, instead of the normal layout filled with dashes. A **Live** indicator next to the title pulses while readings are arriving and turns into an amber **Stale** warning the moment they stop.
- **Carrier counts on the radio page are now counted, not inferred.** The number of active carriers is worked out from the bands the modem actually reports, which fixes 5G connections that could show one carrier fewer than they really had.
- **Cellular and Radio Information speaks all five languages.** The whole page, including the new band details and every state screen, is translated into English, Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano), and Indonesian (Bahasa Indonesia).
- **A friendlier "page not found."** Hit a broken bookmark or a mistyped link and you now land on a branded 404 that speaks QManager's language — an animated signal meter reaching for a lock it can't get, the exact address you asked for, and a one-tap **Return to Dashboard** — instead of a blank error page (new `not-found` route styled to match the login/splash screens; works in light and dark).
- **Antenna Alignment has been redesigned, in all five languages.** The page under **Cellular** now leads with the live aim instrument, then the three-position recorder, then a compact **Receive Chains** strip that links across to Antenna Statistics — translated into English, Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano), and Indonesian (Bahasa Indonesia). Clearing one recording or resetting all three now asks you to confirm first, and an idle antenna is stated plainly instead of being faded out.
- **Antenna Statistics now speaks all five languages.** The whole page — the context strip, every port block and both empty states — is translated into English, Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano), and Indonesian (Bahasa Indonesia). The breadcrumb above it follows your language now too, on both antenna pages, instead of always reading English.
- **SMS Center now speaks all five languages.** The inbox, compose dialog, and message views under **Cellular → SMS Center** are fully translated into English, Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano), and Indonesian (Bahasa Indonesia), matching the rest of the localized interface.
- **Smoother dashboard status changes.** The Network Status, Device Information and 4G/5G cards now ease between states instead of snapping — signal readings dip as they update, status chips fade between colours, and the signal meters glide to their new level instead of springing past it and settling back (motion retuned onto the shared 180/300/400ms token scale).
- **Dashboard readings now tick one after another instead of the whole card blinking.** Every live figure on the dashboard used to flash at the same instant on each poll, so the card flickered as one block; the numbers that actually changed now dip in reading order — top to bottom, or left to right on the Data Used and Carrier Aggregation rows (only the values that moved are staged, so there are no silent gaps and the cascade never outlives the poll that started it).
- **That tick is also slower and easier to follow.** The dip was quick enough to register as a flicker rather than something you could actually watch; it now takes its time on the way down and fades back at a steady rate instead of snapping most of the way home and creeping the rest (700ms end to end, staged 100ms apart, with a linear return so none of that time is spent below the threshold you can see).
- **Status chips finish their colour change properly.** Chips on Recent Activities, Live Latency and the 4G/5G cards now fade their label and icon together as the fill changes colour, instead of the icon snapping in a single frame or the words not moving at all — which matters because the icon is what tells the states apart if you can't rely on colour.
- **Recent Activities now highlights what's recent and what's still wrong.** The dashboard's activity list has been redesigned in the new tonal style, with a header chip reading **All clear** or a count of what's outstanding (each "Internet Lost" is paired with the "Internet Restored" that cancels it).
- **Recent Activities fades out old news, but never an open problem.** Rows on the dashboard's activity list stay highlighted for their first hour and then quiet down to a plain row with a coloured icon, except a problem that still hasn't recovered, which stays lit however old it is (routine band changes and cell handoffs get a neutral tint rather than a colour, so they never read as good or bad news). The list now shows the five most recent events instead of six.
- **Activity names now speak your language.** Every event label in the dashboard's Recent Activities card, from "Cell Handoff" to "Tower Lock Failover", is translated into all five languages, alongside the timestamps and the new status chip.
- **Your activity history goes back a lot further.** The dashboard keeps six times as much event history on the modem, so a busy few minutes on the radio can no longer push the outage you're trying to find off the end of the list (300 events retained instead of 50, with the same amount sent to your browser — no extra load).

- **The Speed Test now warns you what a run costs.** A line under the Run button tells you a test uses roughly 300–500 MB before you spend it — which matters on a metered SIM, and is easy to be surprised by since a *faster* connection actually burns more data (the test runs for a fixed time, not a fixed number of megabytes).
- **You can close the Speed Test while it's running.** The dialog used to silently ignore the X, Escape and clicking outside for the ~40 seconds a test takes; it now closes whenever you like, and reopening it re-attaches to the run still in progress.

- **SMS Center has been redesigned.** **Cellular → SMS Center** now opens with three summary tiles — unread count, modem memory, SIM memory — above a cleaner inbox in the same tonal style as the rest of the refresh, with the unread marker now a proper icon rather than a coloured dot that vanished in greyscale.
- **You can finally see how full your SIM is, separately from your modem.** The storage meters are now split: your modem holds 255 messages and your SIM 35, and they fill up independently. The old single "64/290" reading added two unrelated capacities together and made a nearly-full SIM look comfortable (needs this update on the device; older installs fall back to the combined meter automatically).
- **Clearing your inbox now shows what it's actually doing.** "Delete all" walks the two memories one at a time and reports each — so if the SIM fails and the modem succeeds, it says exactly that instead of one merged error.
- **SMS Forwarding's status card says what it means.** Waiting on a destination number is now shown in blue as a setup step rather than amber as a problem, and each of the four states — active, delivery issues, needs setup, off — has its own icon, so they still read apart in greyscale or with colour-blind eyes.

- **Save buttons across QManager got a proper confirmation.** Every Save, Apply and Update button now fades from its label to a spinner and then to a tick, without the button changing size or the row around it shifting — so you can see the save land instead of guessing (the three states share one slot, so the button is always as wide as its longest state, in any language).
- **Pressing Enter to save no longer loses your place.** Saving used to switch the button off for a moment, which knocked keyboard focus back to the top of the page; the button now stays focused for the whole save and simply ignores a second press.
- **Your settings survive a power cut during an update.** Config files rewritten by an update are now swapped into place in a single step instead of being rewritten in the open, so losing power mid-update can no longer leave one half-written on flash (also cleans up leftover scheduling entries from pre-timer versions, which a bug could previously skip entirely).

## 🐛 Fixes

- **Buttons work the instant a dialog closes.** Closing any dialog used to leave the page ignoring clicks for about a second — most noticeable on **Cellular → Custom SIM Profiles**, where you're opening and closing dialogs constantly — so a second tap simply did nothing. Dialogs, alerts and side panels now close in a third of the time and the page is live again as soon as they're gone (the underlying dialog library disables clicks on the whole page until the close animation finishes, and the backdrop was fading out well before that, which made the app look ready when it wasn't).
- **Recent Activities was only showing half of what happened.** The dashboard's activity feed logged what the background services did but silently threw away everything the web interface itself did — APN saves, profile changes, deactivations — so a change you just made never appeared. All events now land in the same feed (the log file was being created owned by the wrong user at boot, which locked the web interface out of it; it's now pre-created for both, and a dropped event says so in the log instead of reporting success).
- **Applying a SIM profile no longer shows you the last apply's progress.** The step-by-step dialog under **Cellular → Custom SIM Profiles** could sit on a stale result from a previous activation and never update, most often showing an old "complete" the moment you pressed Activate. Progress is now written where both the interface and the background worker can reach it (same file-ownership fix as above — the progress file was being replaced with one the web interface couldn't write).
- **Two profile activations can no longer run at once.** The lock that stops a second apply from starting while one is in flight was being destroyed on every run, so the web interface was effectively running unlocked; it's now kept intact for the life of the boot.
- **Closed a security hole that let the web interface take over the modem's background services.** A settings file that QManager's background services read as root was sitting in a folder the web interface can write to, so anything that got into the web interface could have taken full control of the device. It has moved to `/etc/qmanager.env`, out of reach — your update carries any existing log-level or ping overrides across automatically, but if you hand-edited `/etc/qmanager/environment` over SSH, that is the new path to edit from now on.
- **Applying a SIM profile now really does change your APN.** Activating a profile under **Cellular → Custom SIM Profiles** could tick the APN step green while your modem carried on using the old APN — the step now re-attaches to the network and confirms what the carrier actually granted before reporting success (your APN only reaches the carrier at attach time, and the old check read back the modem's own stored setting, which always matched; expect a cellular drop of around ten seconds while a profile's APN is applied).
- **An APN save and a profile apply can no longer trip over each other.** If a profile activation is mid-way through re-attaching, saving on **Cellular → APN Settings** now says the modem is busy and asks you to try again in a moment, instead of both changes fighting over the connection.
- **An APN your carrier quietly refused no longer reports as saved.** Saving on **Cellular → APN Settings** now checks what the network actually granted and tells you when it differs from what you asked for, instead of reporting success the moment the modem accepted the setting locally (a carrier can hand back a different APN than the one requested — QManager now compares the two rather than reading back its own stored copy).
- **Your APN settings are actually remembered now.** **Cellular → APN Settings** would apply your APN to the modem but forget it the moment you left the page, and profile names on the slot list went the same way — the files behind both were being written to a folder the web interface isn't allowed to create files in, so every save silently did nothing. They've moved to a folder it owns, and your existing settings are carried over automatically on update.
- **Your IP address, gateway and DNS on the APN page are right again.** On an IPv6 or dual-stack connection the page could show a blank IPv6 address, no DNS servers at all, or your gateway listed as a DNS server. All three were the same misread of the modem's reply and are now handled correctly (the modem reports IPv6 as sixteen dotted numbers rather than colon-hex, and quotes the gateway only sometimes — both threw the old parser off).
- **The MTU page no longer reads the wrong connection.** **Network → MTU** always read from the modem's first data channel, but the live one moves between channels each time you re-attach — so it could report the MTU of a channel that isn't carrying anything. It now finds whichever channel your traffic is actually on.
- **Deactivating or deleting a SIM profile no longer returns an unreadable response.** Turning off a profile under **Cellular → Custom SIM Profiles**, deleting an active one, or switching SIM slots could fail in the interface even though the change went through on the modem — the reply contained two answers stuck together and the page couldn't read either (a schedule-teardown helper was printing its own result into the response body).

- **Fixed a reboot loop after upgrading with Scheduled Reboot enabled.** If you had **System Settings → Scheduled Operations → Scheduled Reboot** turned on, v0.1.13 could reboot the modem every 30–60 seconds whenever a SIM was installed — this update makes every QManager schedule ignore the one false trigger that fires while the modem is still setting its clock at boot (the modem has no clock battery; boots start at 1970 and systemd fires armed timers once when the network sets the real time).
- **A band lock applied by a SIM profile can no longer strand you offline.** If a profile's scenario locks bands your area can't serve, QManager now watches for a lost carrier and automatically reverts to all supported bands — the same safety net the manual Band Locking page has always had. This mattered most here, because binding that scenario also disables the Band Locking page, so there was no manual way back (opt-in via the existing band-failover setting; built-in Balanced/Gaming/Streaming scenarios are unaffected).
- **Recent Activities is no longer buried in band-change spam.** When your connection drops, the modem hunts through several bands before settling — and every step used to be logged, filling the entire dashboard activity list in about 12 minutes and pushing out the outage that caused it. QManager now waits for the band and cell to hold steady before logging anything, and reports it as **"LTE band settled on B28 (was B41)"** so it never claims a hop the radio didn't make.
- **A dropped signal no longer wipes out what the radio was doing.** Readings taken while you have no service used to overwrite the last good band and cell, which hid half of what happened and left messages like "5G NR anchor lost (was …)" with nothing after "was". Blank readings are now ignored instead of remembered.
- **"No Events" no longer means "we couldn't check."** If the dashboard fails to load your activity log, Recent Activities now says so and shows the reason, instead of displaying the reassuring empty state as though your network had simply been quiet (and if it already had events on screen, it keeps showing them with a notice above rather than blanking the card).
- **The radio page no longer shows frozen readings as though they were live.** If the modem stopped answering, **Cellular and Radio Information** kept displaying its last numbers with nothing to say so — and could announce every one of your bands as "released" when it was really just a missed read. It now flags stale data and holds the band list steady instead.
- **A band could look "released" without actually dropping.** The radio page and the dashboard's Carrier Aggregation strip both timed a carrier's release off *when the screen last redrew*, not off when the modem last reported it — so an unrelated screen update could occasionally nudge a still-active carrier over the release threshold. Both now time strictly off actual data arriving.
- **An idle antenna no longer reads as a failing one.** Ports your modem isn't using were being shown as a real "-140 dBm / Poor" reading with an empty bar, which looked like an antenna problem worth chasing; they now say **Not reporting**. Antenna Alignment was affected too, where an unused 5G chain could be listed as Active (the modem signals an idle port with values that sit exactly on the bottom of each scale — both pages now read them through one shared check).
- **Antenna Statistics no longer claims "no signal" when it can't reach the modem.** If the very first reading never arrived, the page used to show two "No LTE/5G Signal" panels — blaming the radio for a problem that was actually the connection to the device. It now says the modem is unreachable and offers a Retry, and flags stale readings the moment they stop updating.
- **Your recorded antenna positions can no longer re-rank themselves.** The recommended aim was scored using whichever radio the modem happened to be on at that moment, so a routine 4G/5G switch could quietly crown a different position while you weren't looking. Each recording is now scored purely from what it actually measured, so the winner only changes when you record something new.
- **"Averages 3 samples" now really means three.** The recorder counted every reply from the modem as a sample, but the modem only produces a fresh reading every ~4 seconds — so a recording often averaged the same measurement twice. It now waits for genuinely new readings, which takes about 8 seconds, and the card says so.
- **A recording is no longer punished for an idle antenna.** If one of the two readings behind a position's score was missing, that position lost a flat 40 points for a reason that had nothing to do with where you were pointing — occasionally handing the recommendation to a worse spot. The score is now reweighted across the readings that did report, and the slot marks itself as a partial result.
- **Antenna Alignment no longer claims "no antenna data" when it can't reach the modem.** If the very first reading never arrived, the page blamed the radio for what was really a lost connection to the device. It now says the modem is unreachable and offers a Retry — with a separate amber screen for the genuine case where the modem answers but no antenna is reporting, which is usually worth checking a cable for.
- **The 4G and 5G cards line up again in Italian.** A long heading could push one card's title onto a second line while the card beside it stayed at one, knocking the pair out of alignment; long headings are now trimmed instead of wrapping.
- **The profile form no longer repopulates itself after you edit a profile.** A SIM read that finished while you were editing could re-fill the form the next time you opened it; that stale response is now discarded instead of queued.
- **"Active" and "Not Active" scenario chips can now actually be told apart.** The Connection Scenarios detail card marked its status with nothing but a coloured dot, which read the same in greyscale or to colour-blind eyes; each status now carries its own icon.
- **Your SMS inbox works again after an update.** Texts from both the SIM and the modem's own memory show up in **Cellular → SMS Center** again on devices that upgraded over-the-air, where the inbox could previously come up empty (in-app "Software Update" upgrades now refresh the bundled `sms_tool` binary they used to skip — the older stranded copy talked to the wrong device).
- **Clearing remembered SIMs now clears the list too.** Pressing **Clear** used to drop the count but leave every SIM sitting in **Tracked SIMs**; the count and the list now reset together, keeping only the SIM currently in the modem (they are two separate stores on the device and only one was being wiped — the SIM you're using keeps its dismissed-alert setting either way).
- **Dismissing "New SIM card detected" now really sticks — on the modem, not just in your browser.** The dismissal used to be remembered only by the browser you clicked it in, so the banner came back on your phone, on another laptop, or after clearing site data. It's now stored on the device per SIM and survives reboots and updates (the old dismiss request quietly failed on the device and reported success anyway; it's been replaced with a proper privileged write).
- **The wrong phone number no longer sticks around after a SIM swap.** If you switched to a SIM with no number provisioned — common on prepaid and data-only cards — QManager kept displaying the *previous* SIM's number. It now correctly shows "No number provisioned" instead (also made the number parsing robust against carriers that put a comma in the SIM's name field).
- **Tightened permissions on the folder QManager's system helpers load code from.** This folder was world-writable, which could have let a local attacker on the device replace one of those files and have it run with full privileges. It's now locked down, and the fix re-applies itself on every update so existing devices are repaired automatically.
- **Tightened permissions on QManager's own program folder.** The folder holding the web console was world-writable, which could have let a local attacker swap in their own console program to be run with full privileges at the next start. Now locked down, and repaired automatically on update.
- **Tightened permissions on the HTTPS certificate folder.** The certificate folder and the public certificate were world-writable, which could have let a local attacker replace them and intercept your connection to the QManager web interface. Both are now locked down, with the private key restricted on every update.
- **Tightened permissions on the web root.** The folder QManager serves the web interface from was world-writable, which could have let a local attacker on the device tamper with the pages and scripts it serves. Now locked down, and repaired automatically on update.
- **Tightened permissions on QManager's settings folder.** The folder was world-writable, which could have let a local attacker swap out the settings file QManager's background services read at startup and have their own commands run with full privileges. Now locked down, and repaired automatically on update (the file itself was already protected — but on Linux, replacing a file only needs permission on the folder around it).
- **An update can no longer stop partway through.** On a small number of devices, a config check during the update could fail and take the whole update down with it — after QManager's services had already been shut down for the upgrade. That check now logs a warning and carries on.
- **Tightened permissions on the scheduling folder and the background-service settings file.** Both were writable by the web interface, which could have let a local attacker influence code that runs with full privileges. The settings file is repaired the moment you update; the folder is repaired on your **next reboot after** updating, since that's when QManager's boot setup runs.
- **All your known SIM cards now show up under "Tracked SIMs".** Updating could print `WARNING: failed to seed sim_registry.json` and leave every SIM except the one currently inserted missing from the list — and a missing SIM couldn't be dismissed. This update fills in the gaps automatically, and won't touch SIMs you've already dismissed or renamed (the setup step used a text-matching feature the device's JSON tool ships without; the real error was also being hidden behind that generic warning).
- **Connection Quality settings can save again if the file behind them is ever damaged.** If the probe-target file on the device was left in a bad state, every save under **System Settings → Connection Quality** failed with a write error while the page kept showing defaults as though nothing were wrong — with no way to recover from the web console. QManager now rebuilds that file instead of refusing to write, from both the Connection Quality page and the Watchdog that shares it (the save merges into a JSON object, so anything else aborted it; the merge is now shape-checked and never promotes an empty temp file over a live config — re-save your probe interval on **Monitoring → Watchdog** if it was lost).
- **A successful speed test can no longer report itself as failed.** With the dashboard tile and the Speed Test dialog both watching a run, whichever one collected the result first could delete the log the other was still reading, turning a finished test into an error card. Only one of them harvests the result now, and the other simply waits (a file lock around the result collection; the loser gets a "still running" answer and retries).
- **Devices whose speed-test tool never downloaded now repair themselves.** If the Ookla download failed when QManager was first installed — offline, or a flaky cellular link — Speed Test stayed permanently dead with no way back. Updates now retry the download every time, so an affected device fixes itself on this update (the download used to sit inside a step that in-app updates skip entirely).

- **Your inbox no longer vanishes when the modem is busy.** A failed refresh in **Cellular → SMS Center** used to blank the message list, even though the usual cause is another part of QManager holding the modem for a second. Your messages now stay put, with a notice and a "Stale, 09:14:02" tag saying how old they are.
- **Reply is no longer offered on messages you can't reply to.** Texts from senders like GLOBE, SMART or NDRRMC aren't phone numbers, so replying to them always failed at the modem. The button is now hidden for those, with a short line explaining why.
- **Selected messages could be deleted after you filtered them out of sight.** Ticking a message under **All**, then switching to **Unread** or typing in the search box, left it selected and invisible — and "Delete N selected" still deleted it. Changing the tab or the search now clears your selection, and deletes only ever touch messages you can currently see.
- **SMS Center and SMS Forwarding now really do speak all five languages.** Both pages had shipped with around a hundred labels stuck in English for Simplified Chinese (简体中文), Traditional Chinese (繁體中文), Italian (Italiano) and Indonesian (Bahasa Indonesia); every one of them is now translated.
- **Save buttons no longer switch back to English mid-save.** Most Save and Apply buttons showed a translated "Saving…" and then snapped back to an English label when they finished — every one of them is now translated in all five languages.
- **The confirmation tick at the end of a save was never actually appearing on five pages.** TTL & Hop Limit, MTU, System Settings, Alerts and Watchdog all jumped straight from "Saving…" back to the plain button, so you had only the toast to go on. All five now show the tick properly (each page rebuilt its form the moment the save's refresh landed, discarding the button's state in the same frame it was set).
- **Saving on Alerts or Watchdog no longer throws you back to the first tab.** Editing your email settings under **Monitoring → Alerts** and pressing Save used to dump you back on **Routing**; **Monitoring → Watchdog** bounced you to **Detection**. You now stay where you were, and your show-password toggle and place in the recovery list survive too.
- **Saving no longer makes the activity lists blink and reload.** Every save under **Monitoring → Alerts** and **Monitoring → Watchdog** quietly re-requested the activity log from the modem and flashed it back to loading placeholders. Both now sit still, and each save costs one fewer round trip to the device.
- **Replacing an app password now clears the box.** Under **Monitoring → Alerts**, typing a new email app password or Discord bot token over an existing one left it sitting in the field with Save still lit, as though it hadn't gone through. Both are cleared on a successful save now.
- **System Settings no longer re-animates itself every time you save.** The whole card faded and slid back into place after each save; it now simply updates, which also means it stops moving for anyone who has reduced motion switched on.
- **SMS Forwarding no longer says "off" before it has read your settings.** If the first read came back empty, **Cellular → SMS Forwarding** drew the form with the switch off and the number blank, which looked like a definite answer. It now says it couldn't load your settings and offers a retry.

- **The Back button no longer traps you after being sent to the login page.** Opening a page while signed out sends you to **Login**, but the page you came from stayed in your history — so pressing Back bounced you straight to Login again. That redirect no longer leaves a history entry.

## 📥 Installation

### Upgrading from v0.1.13

**System Settings → Software Update** → Download → Install. No SSH/ADB needed. All settings preserved.

### Fresh Install

> **No SimpleAdmin required.** QManager installs completely standalone — you do **not** need to install (or uninstall) SimpleAdmin or the RGMII toolkit first. The installer bootstraps everything itself (Entware, web server, users, services).

SSH or ADB into the modem and run:

```sh
curl -fsSL -o /tmp/qmanager-installer.sh \
  https://github.com/dr-dolomite/QManager-RM520N/raw/refs/heads/main/qmanager-installer.sh && \
  bash /tmp/qmanager-installer.sh
```

No `curl`? Use `wget` — the installer works either way:

```sh
wget -O /tmp/qmanager-installer.sh \
  https://github.com/dr-dolomite/QManager-RM520N/raw/refs/heads/main/qmanager-installer.sh && \
  bash /tmp/qmanager-installer.sh
```
