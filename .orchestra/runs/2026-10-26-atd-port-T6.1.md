## Design (RM520N deltas from RM551E)
1. **Monotonic deadlines, not `cycle_count %`.** RM520N sleeps *after* the body (period 2.6–4 s,
   and shorter when AT is skipped), so a modulo gives a wrong wall interval. Each AT group keeps a
   next-due uptime: idle touch every 15 s, deep every 60 s; Tier 2 at most every 60 s in idle and
   300 s in deep. Uptime read with builtins from `/proc/uptime` once per cycle.
2. **Heartbeat = content change, timed on uptime.** The CGI writes `$$` in place with a builtin
   (`echo $$ > /tmp/qmanager_ui_active`): zero forks per fetch (T6.2 counts CGI forks). The poller
   records `_HB_SEEN_MONO` when the content changes; empty or torn reads count as no change. No
   wall clock anywhere in tier logic, so the 1970 boot window and the ~24 s clock step cannot flip
   a tier.
3. **No boot seed file.** RM551E seeds by writing the file as root. On RM520N `/tmp` is sticky, so a
   root-owned file blocks the www-data writer for the poller's whole life. Seed in memory instead
   (`_HB_SEEN_MONO` = start uptime → one Active grace after every start).
4. **Tiers.** Active (≤ 20 s since last change): today's cycle unchanged. Idle (≤ 300 s): touch =
   serving cell + QCAINFO + per-antenna; Tier 2 by its own deadline. Deep: serving cell only (its
   RSRP feeds `qmanager_tower_failover`, read every 20 s); CA keeps last values (the zeroing
   else-branch stays inside the not-deep guard). `TIER2_REFRESH_FLAG` (written by
   `cellular/settings.sh` and the poller) forces one full Active touch, then releases.
5. **Outside the gate, every cycle:** `update_proc_metrics`, `update_system_health`, ping/DNS reads,
   `detect_data_connection_events`, `check_alerts`, `crash_watcher_check`, `update_data_used`,
   `update_conn_uptime`, `write_cache`; every 10 s by deadline: `append_ping_history`,
   `read_watchcat_state`. **Inside the gate:** AT reads, `parse_*`, `determine_service_status`,
   `detect_events` (they diff AT state). `SIP_DELAY` sleeps go with their AT call, so skipped
   cycles also skip those `sleep` forks.
6. **Constants, no config keys.** Built-in defaults only (config.sh has no key migration; a settings
   page is a later, separate task).

## Risks
- **The `read` leak fix must land first.** It is uncommitted in `qmanager_poller` (T1.2 session).
  T6.1 branches after that commit; otherwise RSS drift confounds the tier numbers.
- **1970 boot window / clock step:** tier, deadlines and heartbeat age use uptime only. The existing
  long-flag guard (`stat` mtime vs `$SECONDS`) is untouched. Prove by one cold boot (needs OK).
- **status.json shape parity:** only additive keys (`mono`, `device.poller_tier`, `watchcat.age_sec`,
  `watchcat.stale_after`). Gate: 50 snapshots per tier, every existing path and type identical to a
  T1.2-build capture. Discord bot `cache.go` ignores unknown keys (Go `encoding/json`).
- **Stale data for non-UI readers:** tower failover sees RSRP up to 60 s old in deep (same as RM551E);
  the Discord bot `/status` shows signal up to 60 s old (open decision 2); events (band/PCI change)
  are detected at touch time only.
- **Sticky `/tmp`:** a root-owned heartbeat file kills the heartbeat — no root writer anywhere (S1 no
  seed; S5 detects a leftover).
- **Login page keeps Active:** `public/overview.sh` is unauthenticated, so anyone polling it holds the
  tier (accepted on RM551E).
- Watchcat validation needs the watchdog enabled on the device.
