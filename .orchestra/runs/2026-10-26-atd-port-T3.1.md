## Design
### Platform key (D13) — `qm_hw_atd_enabled` in `hw_profile.sh`
Returns 0 only if `qm_hw_model` matches `RM520N*`; else 1 (RG501Q, unknown, unreadable). Explicit
`return 0`/`return 1`, never falls off a `case`. Parser consumer → no root decision reads `platform.json`.
One shell function; the Rust `qsms` must use the same rule (A1), so T8.1 lifts both together.
**Why not in the unit:** systemd 239 ignores `ExecCondition=`; a failing `ExecStartPre` loops into
StartLimit. **RG501Q gate = the unit file never exists there.** The unit keeps T2.3's
`ConditionPathExists=/usr/bin/qmanager_atd` only as a partial-install guard on RM520N. Unit file unchanged.

### set -e rules (M2) — every new line follows these
- `qm_hw_atd_enabled` only inside `if` / `if !` / `||`. Never bare.
- Conditional removals as `if [ -L x ]; then rm -f x || warn ...; fi` — never `[ ] && rm` (fatal as a
  function's last statement).
- `ln -sf`, `rm -f` of units, `systemctl start qmanager-atd` → `|| warn` (none may stop an OTA).
  `install_file` of the binary → `|| die` (same as atcli; a missing broker on a tarball that ships it is a bad package).
- No new `step` call.

### build.sh (D8)
- Preflight `[ -f "$DEPS_DIR/qmanager_atd" ] || fail` (strict; `bun run package` fails until S1 merges —
  merge order S1 first or together). Copy + `chmod 755`. Add `qmanager-atd` to `CORE_SERVICES` lint.
- `.ignore` row; `dependencies/README.md` row; `dependencies/NOTICE`: `qmanager_atd` first-party,
  statically links musl libc (MIT) + Rust std (MIT/Apache-2.0).
- `dependencies/qmanager_atd` itself is **not committed here** (T5.1 S1 owns it).

### install_rm520n.sh
1. `install_bundled_binaries` (both platforms): install `qmanager_atd` 755 (atcli shape). Outside the
   `cmp -s` branch: if `$BIN_DIR/qsms` is a real directory → warn and skip; else
   `ln -sf qmanager_atd "$BIN_DIR/qsms" || warn`. Then (A5): `if ! qm_hw_atd_enabled; then` remove
   `$SYSTEMD_DIR/qmanager-atd.service` + `$WANTS_DIR/qmanager-atd.service` (`|| warn`) and
   `info "qmanager-atd not used on this model ($(qm_hw_model))"`; `fi`.
2. Unit copy loop (`:1699`): same gate — skip installing `qmanager-atd.service` when not enabled (belt; the
   removal already happened in 1). On RM520N the existing enable loop boot-links it (see Q1).
3. `start_services`: after `systemctl restart qmanager-setup`, before the always-on loop:
   `if qm_hw_atd_enabled && [ -f unit ] && [ -x binary ]; then systemctl start qmanager-atd || warn; fi`.
   Same guard on a warn-only `is-active` verify line. Blocking start (no `--no-block`): it gives the order.
4. Unchanged: `stop_services`, `cleanup_legacy_scripts`, `at_stack_check`, the `atcli_smd11` probe (S6).

## Decision for the user (Q1, from A2)
**Q1. Run the broker at boot from this release, or ship it installed but off until T4.1?**
- **A — always-on now (brief as written).** Boot-linked + started on RM520N. Gains field run-time before
  T4.1 depends on it. Costs ≈ 0.6 % core / 570 kB RSS and turns on the QMI lane early (NAS 0x006C held
  until a modem restart, 2 WDS binds, a 2 s sidecar nobody reads). Proof adds: one reboot, a 2 h soak,
  and one CFUN 0/1 cycle with the broker up (disruptive: radio off ~5 s).
- **B — installed but off.** Binary, `qsms`, unit file shipped; unit in the enable-loop skip list and not
  started; T4.1 flips it on. No runtime change for users until T4.1; P3's install/OTA/uninstall proof
  still runs (start it by hand for the proof, then stop). Deviates from brief item 2.
