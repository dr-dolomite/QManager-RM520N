## Verdict
The port works on the RG501Q-EU as far as a read-only run can show. **No blocker found.** QMI is the
same service set and answers the same for every message the port uses; WMS SMS reads work there as
on the RM520N-GL, as root and as www-data. The armv7 broker binary runs. Every broker precondition
matches or is looser. What is left for T8.1 is proof that needs the user's OK (broker started as a
daemon, SMS writes and an incoming message) and two small code changes (§5).

## 3. SMS on WMS (`qsms`, read-only)
- Default backend on the RG501Q is AT, by design: `client/qsms.rs` `use_wms()` allow-lists
  `Project Name: RM520N*`. So `qsms watch` → `{"error":"unsupported"}` rc 1 is the AT backend
  refusing `watch`, **not** a WMS failure.
- With `QSMS_BACKEND=wms`, as root and as www-data: `status` = ME 11/127, SM 0/35 (same as the AT
  backend's `status`); `list all` = 11 messages, 0 skipped, stat 0 ×1 / 1 ×10, all gsm7; `watch`
  printed `ready` and ran until `timeout` stopped it (rc 124).
- The one unread message (ME index 10, WMS tag 1) was still unread after every list (checked with
  `qmi_probe sms list me` before and after). The AT backend's `list` was **not** run: it uses
  `AT+CMGL=4`, which marks unread messages read.
- Not proven (needs signal, SIM credit and the user's OK): tag round-trip, delete of a self-sent
  message, send (1-part, 2-part, UCS-2), an incoming message's indication through `qsms watch`.

## 5. What T8.1 must change (ranked)
1. **Move RG501Q SMS to the WMS backend** (`client/qsms.rs` `use_wms()` allow-list). Evidence: §3
   reads and registration match the RM520N-GL. Until then the forwarder on RG501Q respawns
   `qsms watch`, which exits `unsupported` at once: one WARN "watch ended" per respawn (backoff caps
   at 60 s, so up to ~1 440 lines a day) and polling through `AT+CMGL=4`, which holds the AT lock and
   marks messages read (`scripts/usr/bin/qmanager_sms_forward:493-547`). Before the flip: the four
   write/indication proofs in §3. If the flip waits, stop the respawn when `watch` says
   `unsupported`. Blocks lifting the skip: no (today's behaviour equals the old `sms_tool` path).
2. **Broker daemon smoke on the RG501Q**, with the user's OK: the T2.3 smoke list (socket mode,
   peers, `Type=notify` on systemd 239, `WatchdogSec` restart, kill -9 restart, RSS, a reading
   second opener on smd11). Blocks lifting the skip: **yes** — it is the only broker behaviour not
   yet seen on SDX55.
3. **Lift the installer skip** by widening `qm_hw_atd_enabled` (`scripts/usr/lib/qmanager/hw_profile.sh:135-141`)
   to `RG501Q*`. The same allow-list is copied in `use_wms()`; decide whether the broker gate and the
   SMS backend move together or separately, and change both on purpose. Then T4.1's qcmd cut-over
   runs on the RG501Q (today its `/usr/bin/qcmd` stays the shell script, md5 `85809f67`).
4. **No change needed**: `fs.protected_regular=0`, `/etc/localtime` on rootfs, rootfs mounted rw,
   systemd 239 directives, `/etc/passwd` 0600, D7 interface names. Record them in
   `platform-matrix.md` and flip the "RG501Q-EU: not run" line in `docs/reference/qmi-probe.md`.
5. **Optional, P7**: NAS 0x005A (LTE Tx/Rx per chain) answers on the RG501Q; per-antenna data could
   come from QMI there while the RM520N-GL stays on AT. WMS NV capacity is 127, not 255; `qsms`
   reads it from the modem, and the SMS summary tiles take it from the backend.
