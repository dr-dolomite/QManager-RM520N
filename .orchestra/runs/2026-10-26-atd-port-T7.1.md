## Design (r2)
**The merge happens inside the poller's existing single `jq` in `write_cache`, not in shell.** Advocate measured on the device: the shell env validator costs ~6.8 ms per pass (43 lines, bash 3.2) and the poller writes every ~2.1 s in idle/deep, ≈ 0.4 points of the core; `--rawfile` of the JSON sidecar plus `try fromjson` costs ~0.7 ms. It also keeps the env contract untouched (no `.`/`:` widening).

1. **Broker (Rust):**
   - WDS 0x002D in `BROKER_READ` (bound clients only; never client-allowed). Codec in `qmi/codec/wds.rs`: TLV 0x10 mask `0x0000FFFF`; decode 0x1E IPv4, 0x20 gateway, 0x21 netmask, 0x15/0x16 DNS, 0x29 MTU, 0x25 IPv6 + prefix, 0x26 IPv6 gateway, 0x27/0x28 IPv6 DNS; absent = null. TLV ids confirmed by a raw dump on device before trusting the codec.
   - Read right after each (re)bind, then every 10 s; cached; null on 0x000F, on `qmi_state != up`, or after a mux change until re-read.
   - JSON gains `wds.settings{ip4,gw4,mask4,dns4[],mtu,ip6,ip6_prefix,gw6,dns6[],read_mono}`.
   - **The JSON is also written to `/var/run/qmanager/qmi.json`** (root 0700, same verified-dir rule as the env). The poller reads that copy, never the `/tmp` one, so a www-data process cannot feed values into status.json (they drive tower failover). `/tmp/qmanager_qmi.json` stays for CGIs.
   - Env unchanged. Cargo 0.6.1 → 0.7.0, proto stays 3.
   - Tests: `allow.rs:141-142` pin gains 0x002D; `allow.rs:152-155` "never sent" assert inverted for bound use (still refused to clients); `qmi_snapshot.rs:788` stale test (calls `conn_state.sh` `cq_env_source`, which does not exist on RM520N) is deleted with the reason in the commit body.
2. **`scripts/usr/lib/qmanager/qmi_merge.sh`** (new, keeps the roadmap name): path constants and the jq filter fragment `QMI_JQ_DEFS` (gates + merge). Guarded source in the poller; missing lib = a stub fragment that emits `source:"at"` and null QMI fields.
3. **Poller:**
   - `_QENG_OK` = 0 at the top of `poll_cycle`, 1 only when `parse_serving_cell` ran on a good reply this cycle.
   - `write_cache` adds `--rawfile qmi <file or /dev/null>` (`[ -f ]` guard, so a missing file never fails the run), `--argjson qeng_ok`, `--argjson at_mono "$_AT_LAST_MONO"`.
   - jq gates (all must hold): `qeng_ok == 0`; `system_state` is not `scan_in_progress`; `qmi_state == "up"`; `registered == true`; `0 <= mono − qmi_mono <= 5`; QMI LTE PCI and EARFCN equal AT's, or AT has no LTE and no NR PCI; RSRP/RSRQ/RSSI are numbers. Then `lte.rsrp/rsrq/rssi` from QMI, `lte.source:"qmi"`; else `"at"`.
   - The SIM-switch gate is dropped (no RM520N writer of `/tmp/qmanager_sim_switch_active`). The scan path returns before the final `write_cache`; the boot `write_cache` passes `qeng_ok=1`.
   - Shell variables are never changed, so `events.sh`, alerts, `service_status` and signal history stay AT-only by construction.
4. **status.json, additive only:** `lte.source`, `device.qmi_read_mono`, `device.qmi_state`, `device.qmi_ssr_count`, `device.at_read_mono` (validation marker), `network.wds` (object or null; null when the sidecar is missing, not `up`, or settings older than 30 s). `network.wan_ipv4` / `primary_dns` stay canonical (CGCONTRDP); `network.wds` is the fresher QMI view.
5. **`types/modem-status.ts`:** optional fields only; no UI.

## Risks
1. Failover/bot/service_status behaviour (Q1 above).
2. 0x002D codec has no upstream reference; TLV ids verified by raw dump, values against CGCONTRDP and `ip`. IPv6 unproven: this APN has no IPv6 today → null, recorded as not proven.
3. `network.wds.mtu` is the network-provided PDN MTU, not `rmnet_data0`'s (`qmanager_mtu_apply` may override that from `/etc/firewall.user.mtu`). Compared to sysfs only while no custom MTU file exists; documented.
4. Stale sidecars after a broker stop: age gates (5 s overlay, 30 s `wds`).
5. SSR not inducible without your OK (drops the data call): the soak proves a stable count, not recovery.
6. RG501Q-EU: broker off → no sidecar → `source:"at"`, `qmi_state:""`. Not run (offline, T8.1).
