## P7c — Device Access / custom web port  (Large)
**Today:** port hard-coded in `scripts/usrdata/qmanager/lighttpd.conf:20,45,53-55`, `qmanager_firewall:32`,
`qmanager_health_check:290,718-727`, `tools/modem-mcp/server.ts:573-593`. Onboarding has 6 steps; `web_port.*` i18n
keys exist in all five catalogs. Device Access has a free CARD_GRID cell.

Design
- **Port file:** root-owned `/usrdata/qmanager/web_port` (`http=N`, `https=N`, optional `prev_http/prev_https` during a
  change), 0644, written only by the helper (in-dir temp + `mv`). Parsed, never sourced. Missing = 80/443.
- **Conf always derived from the port file.** The shipped conf is a template with markers on the three port lines.
  `lighttpd.service` gets `ExecStartPre=/usr/bin/qmanager_web_port render` before the `-tt` step, so every start
  (boot, OTA reboot, `Restart=on-failure`) renders from the port file. `render` writes `lighttpd.conf.new` in
  `/usrdata/qmanager/`, reads the ports back from it, `-tt`s it, then `mv`. On any failure it rewrites the port
  file to defaults and renders 80/443, and never fails the unit. Skips the rewrite when the file is absent/default.
- **Firewall always guards the defaults too:** `qmanager_firewall` PORTS = {80, 443} ∪ configured ∪ prev. Ports
  with no listener cost nothing; a conf/port-file split can no longer expose the UI on rmnet.
- **Redirect:** `https://${url.authority.noport}:<S>${url.path}${qsa}` (port omitted when 443); proven with
  `curl -sI` against a sandbox instance on a spare port before build (`-tt` does not check variables).
- **Validation:** integers 1–65535, no leading zero, H ≠ S, not held by another listener (`/opt/bin/netstat -ltn`),
  and a reserved list: 22, 53, 989 (tpws), 5037, 8080, plus the browser-blocked ports (Chrome/Firefox unsafe list,
  e.g. 1719, 1720, 5060, 5061, 6000, 6665–6669, 10080). Code `port_reserved`.
- **Helper** `scripts/usr/bin/qmanager_web_port`, lib `scripts/usr/lib/qmanager/web_port.sh`, `PATH` pinned
  (`/opt/bin:/opt/sbin:/usr/sbin:/usr/bin:/sbin:/bin`). sudoers grants the bare path, but only `show`, `set H S`,
  `reset` work under sudo; `render` and `apply` take no path argument and refuse when `SUDO_UID` is set. `set`
  validates integers first, refuses while an OTA runs or `/tmp/qmanager_config_restore.pid` is live, writes the port
  file with `prev_*`, then detaches `apply` with the updater's exact pattern (`systemd-run --unit=qmanager-web-port
  --no-block --collect` + LoadState / "already exists" handling).
- **Apply:** flock (`install -d -m 0700` lock dir) → sleep 1 (CGI reply flushes) → firewall reload (union) →
  `systemctl restart lighttpd` (ExecStartPre renders) → wait ≤ 10 s for both listeners → drop `prev_*`, reload
  firewall. Failure → restore old port file, restart, result `rolled_back`. Result in `/tmp/qmanager_web_port_result`
  (root-created via temp + `mv`, 0644), GET `last_result`. Never a reboot.
- **Browser move:** `lib/web-port.ts` (551E) probes the new origin, but navigates anyway after the timeout with a
  "accept the certificate on the new port" note (Firefox keys cert exceptions by host:port, so the probe can fail on
  a working server). Session cookie is host-scoped; localStorage starts fresh on the new origin.
- **UI:** `web-port-card.tsx` in the Device Access cell (CardFoot + confirm dialog), `hooks/use-web-port.ts`,
  `types/web-port.ts`; onboarding `step-web-port.tsx` as step 6 of 7 (optional). CGI `system/web_port.sh`
  GET/POST: `invalid_port`, `ports_equal`, `port_in_use`, `port_reserved`, `busy`, `apply_failed`.

Files (beyond the above): `scripts/usrdata/qmanager/lighttpd.conf` (markers), `scripts/etc/systemd/system/lighttpd.service`
(ExecStartPre), `scripts/usr/bin/qmanager_firewall`, `scripts/etc/sudoers.d/qmanager` (one grant),
`install_rm520n.sh` (helper/lib already installed before the conf copy; call `render || warn` — fail-soft, never
`die` after `stop_services`; `print_summary` prints the port), `uninstall_rm520n.sh` (remove `web_port`,
`lighttpd.conf.new`, so `rmdir /usrdata/qmanager` succeeds), `qmanager_health_check` (label + listen test from the
port file), `tools/modem-mcp/server.ts`, `lan-reconnecting.tsx` comment, `onboarding-wizard.tsx`, installer-gui
URL (Open call 7). Docs: new `docs/reference/web-port.md`, router row, `qmanager-independence.md`, `onboarding.md`,
`passwords.md`, RELEASE_NOTES.

Risks: lockout (rollback on no-listen; browser-blocked ports refused; SSH `qmanager_web_port reset`; 22 never
touched); OTA overwrite (render at every lighttpd start); helper killed mid-apply (port file + ExecStartPre keep conf
and firewall consistent; firewall union keeps the WAN closed); restore or OTA in flight (refused).

Validation (auditor re-gate on code; busybox checker on both devices; qm-verifier)

- **Needs OK (lighttpd restarts, firewall changes on 61368cd2):** sandbox lighttpd on a spare port for the redirect
