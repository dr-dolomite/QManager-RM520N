# T5.0 — QMI WMS SMS probe (RM520N-GL)

> Device: RM520N-GL serial 61368cd2, RM520NGLAAR03A03M4G_A0.304, 2026-10-27. RG501Q-EU not run.
> Tool: `native/qmi_probe` `sms ...` commands (see `docs/reference/qmi-probe.md`). Developer tool only.

## Verdict

| Feature | Verdict | Evidence |
| --- | --- | --- |
| List (0x0031) | **GO** | ME 145 / SM 31, counts = `AT+CPMS` and 0x0036; ~0.5–1.5 ms; root and www-data |
| Read (0x0022) | **GO** | ME 0.4 ms per message, SM ~50 ms; full ME inbox list+read+decode 80–100 ms; never changes the tag |
| Send, single part (0x0020) | **GO** | Delivered to the user's phone intact, 896 ms, as root |
| Send, multi-part | **GO with one gap** | PDUs from `pdu::encode_submit` verified (UDL 160 = 7-septet UDH + 153, concat IE, fill bit); the network rejected both parts with RP cause 21, and a single-part retry got the same, so the SIM had no send credit. Network delivery of a concatenated send is unproven; re-run one 2-part send once the SIM has credit |
| Send as www-data | **GO** | The www-data request reached the network (network-side rejection, not a permission error) |
| Delete (0x0024) | **GO** | By index ~9 ms; by tag (3 messages) 104 ms; `AT+CPMS` count follows; read of a deleted index → `0x0032` |
| Modify tag (0x0023) | **GO** | Read ↔ unread ~9 ms each way; used to restore 53 unread flags |
| Indications (0x0001) | **GO** | One Event Report per stored message (storage + index), delivered to two QMI clients at once while vendor daemons run; AT still sees the message (`AT+CPMS` count, `AT+CNMI` unchanged at 2,1) |
| Multi-part receive | **GO** | 3-part message → 3 indices, 3 indications ~0.6 s apart, 8-bit concat IE in each; `decode_deliver` returns `Concat{reference, part, total}` |
| Storage selection | **GO** | Storage is a per-request TLV (1 = NV = AT "ME", 0 = UIM = AT "SM"); WMS ignores `AT+CPMS` |
| Coexistence | **GO** | No WMS call takes `/tmp/qmanager_at.lock` or opens smd11; ME scans ran at full speed while `sms_tool` held the lock; poller NRestarts 0 throughout |
| Routing (0x0032/0x0033) | **No change needed** | Classes 1/3/none store-and-notify to NV, class 2 to UIM, class 0 transfer-and-ack; nothing was written |

**Overall: GO** for retiring `sms_tool` with WMS, except network proof of a concatenated send.

## What failed or is unsupported

- 0x0030 Get Message Protocol → `0x0019` (CDMA only). Not needed.
- Send failure shape: result `0x0036` plus TLV 0x12 `{rp_cause u16, tp_cause u8}` (seen: `15 00 00` = RP 21) and TLV 0x01 message ref. Rejection takes ~650 ms.
- Not tested: tag/delete on SM (UIM) storage (would touch the user's SIM messages), UCS-2 send, class-0 (flash) receive, behaviour across a modem subsystem restart.

## Side effects found on today's code

- **`sms_tool recv` marks every listed message read** (AT+CMGL). Each SMS page load clears all unread flags; WMS reads do not. 51 flags were cleared by this probe's comparison runs and restored with 0x0023.
- `sms_tool -s SM ...` leaves `AT+CPMS` mem1 at "SM" (the CGI's re-assert hides it). Restored to ME after the probe.
- An SM-storage AT read slows concurrent WMS ME reads (1.3 s for a full scan instead of 0.1 s): the modem serialises SIM I/O internally.

## Design inputs for T5.1

1. **Codec:** reuse `native/qmanager_atd/src/sms/pdu.rs` as is. WMS read data is the same PDU AT+CMGL gives (SMSC octet first); Raw Send takes `pdu::encode_submit`'s bytes including the leading `00` SMSC octet, format 6 (GW PP).
2. **Read/unread:** the inbox must read with 0x0022 and mark read only on an explicit user action (0x0023). Decide whether the UI shows unread state; today it cannot (every load clears it).
3. **No CPMS juggling:** every WMS request names its storage. `qmanager_sms_storage`'s boot `AT+CPMS="ME","ME","ME"` and the CGIs' re-asserts can go, unless AT-side mem3 still steers routing — untested; keep the boot step until a read of 0x0033 after a CPMS change shows they are independent.
4. **"Status" (used/total):** 0x0036 gives max and free per storage; used = max − free.
5. **New-message detection:** replace forward/alert polling with a long-lived WMS client registered via 0x0001 (TLV 0x10 = 1). Registration is per socket, so the owner (broker QMI lane) must re-register after reconnect or a QRTR server restart. Concatenated parts arrive as separate indications; wait for `total` parts (or a timeout) before forwarding.
6. **Reassembly key:** (sender, concat ref, total); refs are 8-bit and repeat — 25 groups in the existing inbox, one incomplete.
7. **Send errors:** map result `0x0036` + TLV 0x12 RP cause into the UI's failure toast; a network rejection returns in ~0.65 s, success ~0.9 s per part. Set a socket timeout ≥ 60 s per part.
8. **Permissions:** www-data can list, read, tag, delete and send over `AF_QIPCRTR` without sudo. Any www-data process can therefore send SMS; keep sending behind the authenticated CGI/broker path.
9. **SM storage is slow** (~50 ms per message); read it only on demand, never in a poll.
10. Delete-all per storage = 0x0024 with storage and mode only (no index/tag) — not exercised; by-tag delete was.
