## Design (r2)
### Lock location
`/run/qmanager_at/` **root:dialout 2770**, lock `/run/qmanager_at/at.lock` root:dialout **0660**.
- `/run` (root 0755) not `/tmp`: only root creates entries there, so the dir and lock cannot be pre-planted.
- Group **dialout**, not www-data (R3): it is the group CGIs actually run with and the group that already gates `/dev/smd11` and the broker socket. A uid outside root/dialout cannot open the lock, so it cannot hold it. (The `radio` uid already owns other modem nodes; the gain is against the other vendor uids.)
- setgid so a lock re-created by the in-process client inherits dialout.

### Crate
- `lock.rs`: `LOCK_DIR`, `LOCK_FILE` = new path. `LockFile` carries `legacy: Option<PathBuf>` (field, not a global, so tests stay isolated; production passes `/tmp/qmanager_at.lock`).
- **Bridge, gated by a root-only marker:** after taking the new lock, if `/run/qmanager_at/bridge` exists (root-owned regular file, in the root:dialout dir), also take the legacy lock — only if legacy is a regular file, owner root/www-data, **nlink == 1** (blocks hard-linking a root 0666 `/tmp` file onto the name). Legacy missing/untrusted while the marker is on → log once, go on without it. Legacy held → drop the new lock, report busy (same budget). Marker and legacy are re-checked **after** the new lock is held, every acquire. Order new → legacy; old code only takes legacy → no cycle.
- Who sets the marker: the installer (when a legacy file exists at install time = forward OTA from old code) and the updater's rollback prep. `/run` is tmpfs → a reboot clears it, so after any reboot on T4.3 the `/tmp` name has no effect at all.
- `open_or_create` (qcmd + qsms in-process): dir present, lock absent → create `O_EXCL|O_NOFOLLOW` 0660 (setgid gives dialout); dir absent → root creates it (mkdir 2770, chown root:dialout, refuses a non-dir / foreign one); a CGI caller logs loudly and returns `modem_busy`. Broker: open, never create (setup and installer create it before atd starts).
- **Long-run flag** (`exec.rs:53`, `/tmp/qmanager_long_running`): any uid can create it and hold every short command at `scan_in_progress`. In this change: `long_running()` honours only a trusted flag (regular, owner root/www-data, nlink == 1); untrusted → ignored + logged. Moving the flag itself is **out of my file set** (writers/readers `qmanager_cell_scanner`, `qmanager_poller`, `qmanager_watchcat`, `init.d/qmanager`) → reported to the PM as a follow-up; the watchcat still pauses recovery on a planted flag until then.
- Tests: bridge on/off by marker; legacy untrusted, hard-linked, held elsewhere; flag trust. Rebuild armv7 musl, record md5.

### Shell
- `qmanager_setup`: dir + lock + chmod 2770/0660 root:dialout at the **top** (no `set -e` there); stop seeding `/tmp/qmanager_at.lock` (`:75-77` removed).
- `install_rm520n.sh`: same creation at the **start of `install_bundled_binaries`** (before the binary swap; runs regardless of `DO_BACKEND`/`DO_START`), idempotent, never truncates an existing lock. If a trusted `/tmp/qmanager_at.lock` exists then → create the marker. Comment `:3946`.
- `qmanager_update` rollback mode only (`:600-652`), before `run_install_with_progress`: **prep** = legacy untrusted (foreign owner / not regular / nlink > 1) → `rm -f`; absent → create www-data 0666 (as v0.1.17 setup did); create the marker; **drain** = polled `flock -x -n` on the new lock, 1 s grain, up to 200 s (no `-w`, no `timeout` dependency), warn on time-out. After one success every holder that started before the marker is done; every later one bridges. Guarded `|| true` (script has no `set -e`).
- `qmanager_health_check`: `t_sms_flock` → new path (root FILE form is fine in a non-sticky dir); comments `:491,569`.
- `uninstall_rm520n.sh`: `rm -rf /run/qmanager_at` explicitly (`/var/run/qmanager` glob does not match it); summary text `:166`.
