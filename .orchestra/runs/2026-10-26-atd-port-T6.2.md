## Goal
With `/dashboard` open, the CGIs it polls cost about 13 points of the core on top of the poller
(T1.2 replay: 38.5 % vs 25.7 % busy). Cut that as close to zero as the cuts allow, without changing
any CGI response shape, without adding polling, and without regressing T6.1 (builtin heartbeat write in
`fetch_data.sh` / `public/overview.sh`; `useModemStatus` stops polling from a hidden tab).

## 2. Measured cost per CGI (RM520N-GL 61368cd2, 2026-10-27 23:24–23:25 PST)
Method: 20 sequential `curl -sk` calls per endpoint through lighttpd (https, as www-data) with a minted
throwaway session (auth guard confirmed live: no cookie → `unauthorized`). CGI CPU = delta of lighttpd's
`cutime+cstime` (mod_cgi reaps the CGI; the CGI's own children roll up). Forks = delta of
`/proc/stat processes`, minus curl's own fork, minus the background rate (14.4/s, measured over 20 s just
before). Poller in `active` tier throughout. Resolution 10 ms/20 calls = 0.5 ms.

floor** of `cgi_base.sh` + auth before the script does any work. Its forks, from source:

+15.6 points open vs closed, of which lighttpd's tree is 13.0 (T1.2 saw +12.8). Corrections (advocate):
the replay ran at 0.81 of the census cadence (300 ticks in 370 s), so at full cadence the tree is ≈ 16;
the tree includes lighttpd's own TLS time, so it is not directly comparable with the 13.8 CGI-only figure.
The other ≈ 2.6 points are the on-device `curl` client, which a real browser does not cost the modem.
The fork column is ± ≈ 2 per call (the poller's background forks come in bursts of ≈ 39 per cycle and
each 20-call run spanned 1–5 cycles); the after-build run uses a tighter method (see §4).

A **hidden** dashboard tab today keeps rows 4–10 running while T6.1 drops the poller to `deep`. Their
nominal cost is ≈ 10.6 points, but Chrome throttles timers in a tab hidden for 5 min to about once a
minute, so the steady hidden cost is probably ≈ 1 point. Not measured in a real browser.

Other facts the review surfaced (verified):
- The home cadence is `connectivity.history_interval_sec × 1000 + 250` ms (`home-component.tsx:37-42`);
  the user can set that interval to 1–60 s (`settings/ping_profile.sh:259-270`). The poller's active

  heartbeat fresh on every page.
- `auth/check.sh` sets `_SKIP_AUTH=1` and always answers 200 (`check.sh:3,10,16`); `auth-fetch` only
  redirects on 401. The 10 s auto-logout check never detects an expired session.
- `qm_timeout` is called inside `$(…)` by root daemons (`qmanager_ping`, `qmanager_health_check:319,655`);
  `qm_get_cookie` is read through `$(…)` by `cgi_auth.sh:519`, `auth/check.sh:14`, `logout.sh:18`,
  `password.sh:48`.
- `useDataUsed` has exactly one caller (`device-metrics.tsx:172`), which also takes the reset mutation
  from it. `useModemSubsys` has a second caller (`system-settings/modem-subsystem-card.tsx:88`).
- `status.json` carries `.data_used` (`qmanager_poller:2300-2308`) and `.system_health.storage` (`:2371`);

  `storage.total_kb/used_kb` (`:176-177`), never `stale`.

| C2 | One shared `useModemStatus` store (module-level, ref-counted, `useSyncExternalStore` with a server snapshot for the static export). The speedtest result file persists, so no result is lost. |
| C6 | `auth/check.sh` answers with `printf` instead of two `jq -n` (`:10,16`), and uses C3's `qm_cookie_var`. | CGI | ≈ 0.2 | Low: literal bodies, byte-compared. |

Total for the open dashboard: ≈ 12.5 of 13.8 CGI points. Remaining ≈ 1.3 points: `fetch_data` at the home
cadence and the four 10 s pollers, all at the de-forked floor.

**Not counted: lighttpd's own TLS time.** `lighttpd.conf` sets no keep-alive, so lighttpd's default idle
timeout (5 s, documented default, not probed) applies. After C2 most gaps are ≥ 5 s, so a browser may
handshake on most requests (≈ 20 ms each with curl). The after-build check measures this with a real
browser; if it is large, raising `server.max-keep-alive-idle` is a follow-up (an installer-owned config,
Tier 4 — not in this task).

Not proposed: merging endpoints into one bundle CGI (changes request shapes, little gain after C1/C2);
pre-building history JSON in the poller (adds poller work every cycle for < 1 point); `settings.sh`
13× `qm_config_get` → one `jq`, and `about.sh`'s public-IP lookups (one-shots, ≈ 0.6 s CPU per dashboard
mount — a follow-up, not steady state).
