## Design
### 1. Rust client — RM520N contract adapter (`client/qcmd.rs` only)
- `emit`, `Reply::Ok(raw)`: classify `shell_capture(raw)` exactly like shell `qcmd:174-196` — contains `ERROR` → `command_failed`; contains `OK` → success; empty → `command_failed`; else pass through. Log `Command returned ERROR: <cmd>` as the shell did.
- Code edge-map (one function): `scan_in_progress` → `modem_busy`; `modem_not_ready`, `command_timeout`, `invalid_command` → `command_failed`. The real code goes to `qmanager.log`. Callers see the shell's two codes only (raw and `-j`).
- Fallback: when `LockFile::open` is refused, log an error with the reason before `modem_busy` (T2.1 "log loudly").
- Kept as is: `-t` / `QCMD_WAIT_MS` (additive, no caller uses them), long-flag gate (same rc/stderr as the shell's lock timeout, returns at once), `COPS=2/0` as long (R5; outcome for others = `modem_busy` either way).
- Rebuild armv7 musl; new `dependencies/qmanager_atd` md5 recorded. RM520N-local delta noted beside the vendoring decision.

### 2. Installer (`install_rm520n.sh`)
- `install_backend` usr/bin loop: `qcmd` on a `qm_hw_atd_enabled` model → atomic link (`ln -s qmanager_atd tmp && mv -f tmp qcmd`); otherwise (RG501Q, model unknown) install the shell script as today. `scripts/usr/bin/qcmd` stays in the tree for RG501Q and the fallback-of-the-fallback.
- `install_bundled_binaries`: drop the unconditional wants-link `rm -f`. **W1:** remove the unit only on a definite non-RM520N answer; if `hw_profile.sh` did not load, leave unit and link alone and `warn`.
- `enable_services`: drop the `qmanager-atd` skip; boot-link it only if `qm_hw_atd_enabled` (unit is absent elsewhere anyway).
- `start_services`: after `systemctl restart qmanager-setup`, `systemctl start qmanager-atd || warn` (guard: enabled + unit + binary); add it to the verify list on RM520N.
- `qcmd_test` (C11): **deleted** from the tree; installer removes a stale `/usr/bin/qcmd_test`.
- No new `step`; set -e shapes as T3.1 (no bare function calls, no `[ ] && rm` tails).

### 3. Uninstall
No functional change needed (R11). Re-check order: units stopped before binaries go; `rm -f qcmd` removes the link.

### 4. Health check
`svc.atd` on RM520N: `failed` / `inactive` → **fail**. `bin.qcmd` follows the link (`-x`), unchanged.

### 5. RG501Q-EU (D13)
Unchanged: no unit, shell `qcmd`, binary + `qsms` only. Same `qm_hw_atd_enabled` key.

### 6. Lock-dir hardening — proposed split (user decides)
Moving the lock to a `root:www-data 0770` dir touches the crate constant, `qmanager_setup`, `health_check:594`, the shell `qcmd` (RG501Q), and creates two lock domains during any OTA or rollback that crosses it (old shell callers vs broker → concurrent smd11 writes). Proposal: **T4.3**, its own plan. T4.1 keeps only the loud log on a refused open. Log rotation 0666 is already fixed (S1).
