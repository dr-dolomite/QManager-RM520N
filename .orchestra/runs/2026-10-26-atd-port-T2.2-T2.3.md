## r2 changes (qm-advocate, 9 challenges; #1 re-probed by the lead)
1. **Socket group is `dialout`, not www-data.** lighttpd runs uid 33 / gid 20 / groups 20
   (`server.groupname = "dialout"`, probed `/proc/<lighttpd>/status`), so CGIs carry no gid 33 and a
   `root:www-data 0660` socket would EACCES every CGI into the fallback. Socket = `root:dialout 0660`
   (gid via `getgrnam("dialout")`, the group that already owns `/dev/smd11`); peers stay uid {0, www-data}.
2. www-data smoke goes **through lighttpd** (minted session + `curl` to an AT CGI), not `sudo -u www-data`
   (sudo gives groups 20,33 and would hide #1).
3. Path proof = runtime unit with `Environment=QLOG_LEVEL=DEBUG`, grep `qmanager_atd.*AT_CMD`. No lock hold
   (a short hold only delays, a > 5 s hold hits the poller and T6.1).
4. `nobody` is refused at `connect()` (EACCES, not in dialout) and falls back; the peer-uid check itself
   is proved by unit test only.
5. **Broker start also starts the QMI lane**: sampler sends NAS Config Signal Info v2 (0x006C), binds WDS
   clients and writes `/tmp/qmanager_qmi.json`. 0x006C stays set until a modem restart. No off switch;
   adding one is out of scope. Clean-up removes `/tmp/qmanager_qmi.json` and `/var/run/qmanager`.
6. **ExecStopPost dropped**: it would unlink a manually started live broker's socket. The daemon replaces a
   stale socket itself; a stale proto file only makes clients try the socket and fall back.
7. `ConditionPathExists` skips RG501Q only while the binary is absent there; once `qcmd` becomes a link to
   it (T4.1) T3.1 must keep the unit off RG501Q. Open item for T3.1/T4.1.
8. No device step exercises "stop pinging when the lane is stuck" (`kill -STOP` tests systemd's side). Unit test only.
9. Wall-clock is still used by `clear_stale_long_flag` (mtime age, upstream). The unit and restart path use none.

## Design
### T2.2 — peer policy (D2)
- `common/safefs.rs`: `www_data_uid()` becomes `www_data_ids() -> Option<(uid, gid)>` (same single
  `getpwnam`); `trusted_owner` keeps using the uid.
- `daemon/mod.rs`: bind under umask 0177 as now (root-only from the first instant), then
  `chown(sock, 0, dialout_gid)` + `chmod 0660`. Socket ends `root:dialout 0660` (see r2 #1). If the lookup or the
  chown fails: socket stays 0600 and only root is served, logged once (AT still works for www-data via
  the in-process fallback).
- `Ctx.uid: u32` -> `Ctx.peers: Peers` (root + www-data uid, or the test's own uid). Reject message no


### T2.3 — unit + restart (D4): **systemd watchdog in the daemon, no client restart**
- Why not `sudo -n systemctl restart` from the client: detection only after a 340 s client timeout,
  needs a cross-uid marker (www-data cannot create one in `/run`; `/tmp` has protected_regular) and the
  upstream marker ages by wall-clock mtime, wrong across the 1970 step. The watchdog is monotonic on both
  sides and needs no privilege.
- `daemon/at_lane.rs`: the lane publishes `busy_since` (`AtomicU64`, CLOCK_MONOTONIC ms, 0 = idle),
  set before `runner.run`, cleared after the reply write.
- New `daemon/watchdog.rs` (RM520N-local file): if `NOTIFY_SOCKET` is set, send `READY=1` after the
  bind + proto file; if `WATCHDOG_USEC` is set (and `WATCHDOG_PID` is ours or unset), a thread sends
  `WATCHDOG=1` every `WATCHDOG_USEC/3` while the lane is idle or its current job is younger than
  `FROZEN_AFTER` = 340 s (the client's longest exchange). Past that it logs once and stops pinging;
  systemd kills and restarts the broker. Plain `UnixDatagram` to the socket path (abstract `@` name
  handled), no libsystemd. Without systemd (manual run) nothing is sent.
- `client/transport.rs`: drop `claim_restart`, `RESTART_MARKER`, the init.d spawn and their test. An
  uncapped 340 s timeout logs `broker gave no reply in 340s for: <cmd>` and answers `command_timeout`
  as before (never re-run). `CLIENT_REPLY_TIMEOUT` becomes `pub(crate)` so the watchdog uses the same number.
- `scripts/etc/systemd/system/qmanager-atd.service` (LF, like its siblings):
  ```
  [Unit]
  Description=QManager AT Command Broker
  After=qmanager-setup.service
  Wants=qmanager-setup.service
  Before=qmanager-poller.service
  ConditionPathExists=/usr/bin/qmanager_atd
  StartLimitIntervalSec=3600
  StartLimitBurst=5

  [Service]
  Type=notify
  NotifyAccess=main
  ExecStartPre=<the poller's 30 s /dev/smd11 wait>
  ExecStart=/usr/bin/qmanager_atd
  WatchdogSec=30
  TimeoutStartSec=40
  TimeoutStopSec=10
  Restart=on-failure
  RestartSec=5s

  [Install]
  WantedBy=multi-user.target
  ```
  `ConditionPathExists` makes the OTA-enabled unit a clean skip (not a failure) until T3.1 ships the
  binary, and gives T3.1 the RG501Q skip (D13) by simply not installing it. Watchdog kills count toward
  StartLimit (5/h); past it AT keeps working through the in-process fallback. No wall-clock in the unit or the restart path.

## Risks
- Watchdog sees only a stuck AT lane; a wedged acceptor still accepts into the backlog and nobody
  restarts it (same blind spot as upstream's client restart, minus the client trigger). Accepted.
- An smd11 read stuck in D-state cannot be killed by anything; restart stalls until TimeoutStopSec.
- The in-process fallback and the broker share the flock, so a broker running beside shell `qcmd` is
  safe only if the broker never reads smd11 outside the lock — smoke step 3/4 checks it.
- StartLimit 5/h: a modem that wedges repeatedly leaves the broker down until reset-failed; AT falls back.

## Rollback
Revert the branch commits. On the device: runtime unit in `/run`, binary in `/tmp`; only the QMI 0x006C signal config persists until a modem restart.
