# T0.1 — Device feasibility probe (Phase 0)
parent: `.orchestra/runs/2026-10-26-atd-poller-port.md`   seat: modem-investigator   rev: r1   opened: 2026-10-26

## Goal
Measure, on the live modems, whether the RM551E broker's three lanes (AT, QMI, data-call) can run on
the RM520N-GL, and record the facts the platform deltas D2–D7, D12 and D15 depend on. Output is
evidence, not a recommendation; the lead writes the GO/NO-GO.

## Devices
- RM520N-GL: `RM520N_IP` (192.168.225.1, reachable 2026-10-26). Credentials in `.env`
  (`RM520N_SSH_USER` / `RM520N_SSH_PASSWORD`); never echo values.
- RG501Q-EU: `RG501Q_IP` (192.168.120.1). Probe only if reachable; otherwise record "offline".
- Posh-SSH: `New-SSHSession ... -Force`. Prove the device on every capture:
  `cat /etc/quectel-project-version; grep -o 'androidboot.serialno=[^ ]*' /proc/cmdline`
  (RM520N serial `61368cd2`, RG501Q `b7e3d6f1`).

## Rules
- Read-only. No config writes, no service restarts, no AT set commands, no reboots. AT queries only
  through `qcmd` (e.g. `ATI`), never raw writes to the node, except the one bounded test in Q4.
- One uploaded probe script per device in `/tmp`, run by path, deleting itself at the end (the tool
  guard blocks `rm` inside SSH command strings).
- Write captures to `.orchestra/scratch/atd-T0.1-<device>.txt` (gitignored).

## Questions (answer each with the command and its trimmed output)
1. **Runtime:** `uname -a`; libc (`ls -l /lib/ld-* /lib/libc*`); `/proc/cpuinfo` features; `free`;
   `df -h /usrdata /opt /tmp`.
2. **QRTR (D6):** `grep -i qrtr /proc/net/protocols`; `zcat /proc/config.gz | grep -i QRTR`
   (if present); `grep -i qrtr /proc/kallsyms | head`; `ls /proc/net | grep -i qrtr`. Does a socket
   with family 42 open (any small static test, or `cat /proc/net/protocols` showing QIPCRTR)? Is a
   QRTR name service published? List the published services if any tool exists to list them.
3. **QMI holders (D6):** which processes hold QRTR or QMI sockets/nodes:
   `ls -l /proc/*/fd 2>/dev/null | grep -iE 'socket|smd|qmi|cdc-wdm'` cross-referenced with
   `/proc/net/*` socket inodes; `ps` for Quectel/Qualcomm daemons (`QCMAP_ConnectionManager`,
   `netmgrd`, `qti`, `ql_*`, `atfwd`). Also `ls -l /dev/smd* /dev/glink* /dev/cdc-wdm* /dev/qcqmi*`.
4. **smd11 multi-opener (D12), bounded:** with nothing else changed, hold `/dev/smd11` open
   read-write and idle for at most 20 s (`exec 3<>/dev/smd11; sleep 20; exec 3>&-`). Never read or
   write fd 3. In parallel, run `qcmd ATI` and `sms_tool status` (or the nearest read-only
   `sms_tool` verb in use by `scripts/usr/lib/qmanager/sms_alerts.sh`) twice each. Report whether
   each answered normally. If the first `qcmd ATI` fails, close fd 3 immediately and stop this test.
5. **Permissions (D2, D3, D4, D15):** `sysctl fs.protected_regular fs.protected_fifos`;
   `stat -c '%U:%G %a %F' /tmp/qmanager_at.lock /tmp/qmanager_long_running /dev/smd11`;
   `ls -ld /tmp /var/run /run /var/lock`; `id www-data`. As root, does
   `sh -c 'exec 3>>/tmp/qmanager_at.lock'` succeed (exit code)? It appends nothing.
6. **Data-call interfaces (D7):** `ls /sys/class/net`; `cat /proc/net/route`; whether `rmnet_ipa0`
   and `rmnet_data<N>` exist and which one carries the default route.
7. **Current AT owner:** `pgrep -fa qmanager`; `systemctl is-active qmanager-poller`; who holds
   `/dev/smd11` right now (fd scan).

## REA
Not used (user decision r2). If the fd/socket scan cannot attribute QMI clients, record
"could not attribute" with what was seen.

## Done when
Every question has a capture or an explicit "could not measure: <reason>", per device, and the
report gives the status line, the evidence, and what is still unknown.

## Out of scope
Timing and CPU measurements (T0.2), building the crate (T0.3), any change to the repo.
